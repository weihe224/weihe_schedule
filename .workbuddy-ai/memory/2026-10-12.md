## 滚轮循环边界修复（第二次任务，已设备验证）

**需求**：把滚轮从"有限列表"改为**真循环** —— `00` 上方须显示 `22/23`，`23` 下方须显示 `00/01`；分钟 `00` 上方 `58/59`，`59` 下方 `00/01`。

**根因（不是显示文字问题）**：原实现是**有限列表**，类注释明写 *"It does not wrap around"*，且三处都在**截断**而非回绕：
1. `maxOffset() = (count-1) * rowHeightPx`，`setScroll()` 里 `Math.max(0f, Math.min(maxOffset(), px))` —— 首尾截断；
2. `nearestRow()` 里 `if (row < 0) return 0;` + `Math.min(row, count-1)` —— 索引截断；
3. 没有取模，索引就是行号。
所以滚到 `00` 时上方**是空白**（我在设备上拍到了修复前的原始画面：`00` 上方两行全空）。用户看到的 "`13、14`" 是**分钟列**（`00:15` 时分钟显示 `13/14/15/16/17`），两列相邻，被误读为小时列上方的值。

**修法**：改为**无界虚拟索引 + 归一化取模**：
- 新增 `mod(int, int)`（Euclidean modulo，`-1 % 24 → 23`；Java 的 `%` 会给出 `-1`，这是向上取到负数的根因）；
- `valueAt(index) = from + mod(index, count)`；
- `nearestIndex(offsetPx, rowHeightPx)` 不再有上下钳制；
- `INDEX_ORIGIN = 100_000` 行作为起点；
- `onDraw` 按**索引带宽**绘制（`centreIndex ± (VISIBLE_ROWS/2 + OVERDRAW_ROWS)`），不再有首尾行；
- `fling()` 需要传边界（`OverScroller` **没有** 4 参数的"无界"重载），边界取 `here ± rowHeightPx * FLING_RANGE_ROWS`（10_000 行）。

**过程中自己引入并修掉的两个缺陷（都被测试/设备抓到）**：
1. **甩动变成缓慢蠕动**：最初把边界写成 `Integer.MIN_VALUE/4 ~ Integer.MAX_VALUE/4`，但 `INDEX_ORIGIN = 1<<24` 使 `scrollPx ≈ 1.9e9 > Integer.MAX_VALUE/4 ≈ 5.4e8`，于是 `OverScroller.fling` 内部 `if (start > max || start < min)` 命中，走了 `startAfterEdge()` 分支 —— 表现为**长时间缓慢爬行**（连拍 5 帧各不相同）。修法：把 `INDEX_ORIGIN` 降到 100_000 并用**以当前 offset 为中心的**边界，保证 `start` 永远在范围内。
2. **打开时定位错位**：`indexForValue(v) = INDEX_ORIGIN + (v - from)`，但 `100000 % 24 = 16 ≠ 0`，导致 `valueAt(index) ≠ v` —— 打开时不是从原时间开始。修法：先把原点**向下取整到 count 的整数倍**（`turns*count + (v-from)`）。这条是新写的单测 `theIndexChosenForAValueMapsBackToThatValue` 抓出来的。

**测试**：`WheelColumnViewTest` 从 12 项扩到 **27 项**，覆盖任务点名的全部场景：`00` 上方 `22/23`、`23` 下方 `00/01`、分钟 `00` 上方 `58/59`、`59` 下方 `00/01`、向上跨 `00`/向下跨 `23`、连续跨多个边界仍在范围内、`23:59↔00:00` 双向、两列互不干扰、整圈步进不跳值不重复、负索引取模、初始化往返、退化输入。用例以"**可见五行带**"整体断言（`assertBand`），比单值断言更容易暴露 off-by-one。

## 修复：增删节按钮被截断（第四次任务，已设备验证）

**问题**：用户截图指出「添加一节 / 减少一节」两个胶囊按钮看起来被切断。

**定位（像素级，不是肉眼判断）**：用 `screencap` 拉全分辨率截图，写了个纯 Python PNG 解码器
（zlib + 四种 filter 还原）逐像素扫描按钮区域。
修复前按钮**实测高 89px ≈ 34dp**，而 `BUTTON_HEIGHT_COMPACT = 40dp` 在 420dpi（scale 2.625）下应为 **105px**；
且上下圆角被压平成硬边 —— 与截图的"切断"观感一致。

**根因**：`createPeriodButtons()` 里按钮栏与按钮**都是 `WRAP_CONTENT` 高度**，只靠

最终按**文字行高**定尺寸，`minHeight` 未生效。

**修法**：按钮栏给**显式 `dp(UiTokens.BUTTON_HEIGHT_COMPACT)` 高度**、按钮 `MATCH_PARENT` ——
这正是 `CourseDetailActivity`（复制课程那一行）已在用的写法，两处因此一致；
`topMargin` 统一为 `UiTokens.SPACE_M`。

**设备复验**：两按钮 bounds 均为 `h=105`；像素扫描圆角对称（中间 `76..528`、顶 `97..507`、底 `100..504`）；
卡片内边 x=1004、按钮外边 x=1003，未越界。
